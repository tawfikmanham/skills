# Sources and practice examples

## Use a source in a critique

1. Locate the detail and describe what you can see. Use the label, placement, or visible state so another person can find it.
2. Explain how that detail might affect the user’s task. Say which part is an inference.
3. Name the principle that explains the connection. Define it in one sentence and cite the specific article, pattern, or criterion beside the finding. One relevant link is usually enough.
4. Give a change to try, a check to run, or a small exercise. In reviewer coaching, use a parallel example and let the reviewer write their own version.

Cite a heuristic for the design principle, a design system for its component guidance, a standard for the specific criteria it defines, and a research guide for how to test a prediction. A source can support the reasoning behind a finding. The screenshot or research supplies the evidence about this particular product. Keep claims within what each source covers and check the current documentation before stating a specific requirement.

## Pick the source that fits the finding

| When reviewing | What to notice or practise | Source |
| --- | --- | --- |
| Quality of the critique | **Critique objective** is what the design should help the user achieve. Rewrite “I don’t like this layout” by naming the task and the detail that gets in its way. | [NN/g: Design Critiques](https://www.nngroup.com/articles/design-critiques/) |
| Visual hierarchy and grouping | **Visual hierarchy** is the order in which elements draw attention. Name what you noticed first and identify the cue, such as scale, placement, or contrast. Use balance and Gestalt grouping when they explain the finding. | [NN/g: Five Principles of Visual Design](https://www.nngroup.com/articles/principles-visual-design/) |
| Interaction and system state | **Visibility of system status** means the interface tells people what is happening. For an upload, locate the feedback for progress, success, or failure. Ask for the relevant state if it falls outside the screenshot. | [NN/g: 10 Usability Heuristics](https://www.nngroup.com/articles/ten-usability-heuristics/#toc-1-visibility-of-system-status-1) |
| Buttons and error messages | **Action label** is the text that describes what a control does. Compare “Continue” with “Review order” when the next step is an order review. For an error, check whether the message explains the problem and how to recover. | [GOV.UK: Button](https://design-system.service.gov.uk/components/button/) · [GOV.UK: Error message](https://design-system.service.gov.uk/components/error-message/) |
| Navigation or components on an Apple platform | **Platform convention** is a pattern users may recognise from other apps on the device. For an iOS tab bar, compare its role in the flow with Apple’s guidance for navigating between sections. | [Apple Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/) · [Apple: Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars) |
| Accessibility on the web | **Use of colour** asks whether information conveyed through colour has another visible cue. If a form marks errors only with red borders, flag the risk and check for a text message in the relevant state. Measure contrast from the design values or live page when it is part of the finding. | [W3C: Use of Color](https://www.w3.org/TR/WCAG22/#use-of-color) · [W3C: Contrast (Minimum)](https://www.w3.org/TR/WCAG22/#contrast-minimum) |
| A prediction about what users will do | **Task-based usability testing** means observing people as they try to achieve a goal. For checkout, ask participants to check their order before paying and observe which action they choose. | [GOV.UK: Moderated Usability Testing](https://www.gov.uk/service-manual/user-research/using-moderated-usability-testing) |

## Example of a cited finding

> In the checkout summary, the delivery estimate and order total use the same size and weight. A shopper looking for the amount due may need to read both rows. That’s a visual hierarchy issue. Try giving the order total more weight, then ask shoppers where they would look for the amount they’ll pay. [NN/g: Five Principles of Visual Design](https://www.nngroup.com/articles/principles-visual-design/)

On your next screen, write down the first two elements you noticed and the visual cue that drew your eye to each one. Compare that order with what the user needs to find first.
