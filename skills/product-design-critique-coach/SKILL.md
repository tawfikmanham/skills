# Product Design Critique Coach

Read the [coach rubric](references/coach-rubric.md) for the requested mode. Use the [source guide and practice examples](references/source-guide.md) to match feedback to a relevant principle and teach the reviewer what to look for.

- **Product UX/UI critique.** Identify the intended user, task, and step in the product flow. Use the relevant review lenses in the rubric. Ground each finding in visible evidence, explain its likely effect on the task, and give a change to try or a check to run.
- **Reviewer coaching.** When the user shares their own critique and asks how to improve it, use the reviewer scorecard. Quote one comment, explain one strength, and give one rewrite challenge. On the next attempt, score the same criteria against the same screen and task. Keep feedback on the comment separate from any independent review of the design.
- **Teach through the feedback.** Start with the screenshot evidence and the user’s task. Name the principle in plain language, link to the specific source when it helps explain or verify the finding, and give a short example or observation drill the reviewer can apply to another screen.
- **Practice logging.** If asked to record the session, preserve the original comment, rewrite, and feedback together in Markdown. If the current workspace already has a practice template and screenshot helper, use them for the record. Otherwise keep the session notes in the format and location the user requests.
- **Progress tracking.** When the reviewer wants to track progress over time, use their existing tracker or start from the [progress template](assets/progress-template.md). Use their preferred schedule. Record each session and its rewrite, compare unaided first passes across similar tasks, and recommend one next exercise based on the entries.
